# Packages built against Armtix (aarch64) and Artix (x86_64) and published as
# one pacman repo per arch.
#
#   SOURCE NAME [ARCHES [OPTIONS]]
#                          ARCHES is a comma-separated list, default aarch64:
#                          almost everything here exists only because omarchy
#                          publishes no aarch64 build of it.
#                          OPTIONS: nocheck builds without the recipe's test
#                          step, for one whose tests need a package no repo
#                          here carries. Say why beside the entry.
#                          ahead=GROUP carries a group of recipes only while
#                          any member's version is newer than the distro's
#                          own, and then carries every member, so they stay
#                          built against each other. Once the whole group has
#                          caught up it is skipped and dropped from the repo,
#                          and boxes go back to the distro's builds.
#                          ref=COMMIT (arch only) builds Arch's recipe as of
#                          that packaging commit, to hold a member back from
#                          a soname bump the distro hasn't made. Say why.
#
#   omarchy NAME   pkgbuilds/NAME from omacom/omarchy-pkgs (branch master, latest
#                  at build time -- omarchy's own recipes, which already declare
#                  aarch64; omarchy just never publishes the aarch64 builds)
#   local NAME     pkgbuilds/NAME in this repo, for the rare recipe omarchy's
#                  cannot be built from here (see the recipe's header for why)
#   arch NAME      Arch Linux's official recipe (gitlab.archlinux.org/archlinux/
#                  packaging), with this arch added to arch=() -- for packages
#                  Armtix does not carry. Only recipes checked to be portable.
#
# No AUR. Every recipe is omarchy's, Arch's or ours, reviewed in this repo.
#
# ORDER IS BUILD ORDER: a recipe whose dependencies are built here must come
# after them (pinta after dotnet-core-bin).
#
# Only what the boxes cannot get elsewhere: on ARM, not in Armtix, not in
# omarchy's aarch64 repo, not an arch-independent package from its x86_64 repo;
# on x86_64, not in Artix and not in omarchy's repo.
omarchy asdcontrol
omarchy tzupdate
omarchy omasnap
omarchy omacalc
omarchy omacut
omarchy omawrite
omarchy cliamp
omarchy herdr
omarchy hyprland-preview-share-picker
omarchy dotnet-core-bin
omarchy pinta
local   localsend
local   wayland-pipewire-idle-inhibit aarch64,x86_64
# In omarchy's package list, in Artix's x86_64 repos, missing from Armtix.
arch    bluez-tools

arch    nautilus-python
# nocheck: since 6.12.1 Arch's recipe tests with mise, which Armtix does not
# carry (2026-10-11). The build itself needs only cargo.
arch    usage aarch64 nocheck
# Omarchy's Install > Service > Signal (omarchy-install-service-signal).
# Arch's recipe already handles aarch64: Electron arm64, plus Signal's own
# linux-arm64 prebuilds of libsignal, sqlcipher and ringrtc. Built and
# launched on the uConsole 2026-11-25 (8.36.0, ~5 min).
arch    signal-desktop

# Omarchy itself, packaged for Artix (see each recipe's header). In this order:
# omarchy depends on omarchy-artix and omarchy-themes, and makepkg -s installs
# depends from the local build repo. omarchy and omarchy-artix fetch the private
# omarchy-artix repo, so they need the OMARCHY_ARTIX_TOKEN secret. Both arches:
# x86_64 boxes (the workstation) run the same packaged omarchy.
local   omarchy-artix aarch64,x86_64
local   omarchy-themes aarch64,x86_64
omarchy omarchy-themes-intros aarch64,x86_64
local   omarchy aarch64,x86_64
# Omarchy follows Arch's Hyprland the day it lands; Artix and Armtix can be
# days behind, and new config keys then show as errors (0.57's misc.bell_sound,
# 2026-10-31). hyprutils and aquamarine ride along so a Hyprland that needs
# newer ones gets them from us too. Build order: hyprutils, aquamarine,
# hyprland.
#
# hyprtoolkit rode along from 2026-11-02 to 2026-11-25, because it links
# aquamarine (0.16's soname bump). It is out of the group now: Arch's 0.7.0
# moved libhyprtoolkit.so 6 -> 7, and seven distro packages link it
# (hyprland-guiutils, which hyprland needs, hyprlauncher, hyprpaper,
# hyprpolkitagent, hyprpwcenter, hyprshutdown, xdg-desktop-portal-hyprland).
# Carrying it alone kept the whole group "ahead" and broke hyprland's build
# on guiutils. If aquamarine's soname moves ahead of the distro again, put
# hyprtoolkit back (and check that its own soname still matches the distro's).
arch    hyprutils aarch64,x86_64 ahead=hypr
arch    aquamarine aarch64,x86_64 ahead=hypr
# aarch64: back in the group, held at 0.6.0-3 (Arch's rebuild for aquamarine
# 0.16, libhyprtoolkit.so=6). Without it Armtix's 0.6.0 wants
# libaquamarine.so=14, which our aquamarine 0.16 replaces, so hyprland and
# omasnap could not install their deps (pkgs runs a340/a341, 2026-11-26).
# Drop this line once Armtix's hypr stack catches up.
arch    hyprtoolkit aarch64 ahead=hypr,ref=fd308ad88ed0590f574b076515231f3507808e5a
arch    hyprland aarch64,x86_64 ahead=hypr
